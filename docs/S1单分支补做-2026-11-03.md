## 1. 目标与边界

只补两个命名实验臂，回答“版本门控”和“写路径”的分别作用：

| 实验臂 | 读缓存未命中回填 | 写路径 | 复用关系 |
|---|---|---|---|
| `B-gate-only` | 版本门控 `PutIfNewer` | 提交源后 `DELETE` | 新组合：cache-aside 的删除写 + S2 的门控回填 |
| `B-write-only` | 普通 `SET` | 提交源后普通 `SET` 回填 | 与既有 `B-off` 逻辑完全相同，仅换臂名 |

本阶段没有改动旧 A/B/B-off/C/CV/D 分支语义，也没有打开 Stream 消费者、L1 或 S2 任何行为。没有新增自然负载、直写、C/CV/D、不同延迟/速率/读写比或探针。

## 2. 代码变更

- `experiments/e1-shopping-guide/cmd/guide/main.go`
  - 新增实验开关 `GUIDE_GATED_ASIDE=1`：只在 `CACHE_READ_MODE=cache-aside` 时，把 cache-aside 的读未命中回填改为版本门控；写路径仍是原有的写后删除。默认未设置，原行为不变。
  - `/debug/strategy` 在原有 `source/mode/ungated_fills/ttl/fill_delay` 之外增加 `gated_aside`、`read_fill_gated`、`write_path`，用于运行时核对实际分支。
- `experiments/e1-shopping-guide/internal/guide/strategy.go`
  - 增加只读描述方法 `ReadFillGated()`、`WritePath()`，供上一条的调试端点使用；不改变任何读写分支。
- `experiments/e1-shopping-guide/internal/guide/strategy_test.go`
  - 用记录型缓存区分 `PutIfNewer`/`Set`/`Delete`，确定性验证：
    - gate-only：GET 未命中走门控回填，PUT 只删除；
    - write-only：GET 与 PUT 都走普通 SET；
    - A/B/B-off/两个新臂的 `read_fill_gated` 与 `write_path` 描述一致。
- `scripts/p2/s1_single_branch.py`
  - 单分支补测控制器。固定 50ms 读源回填延迟、95:5、400 req/s、warmup 10s、window 32s、seed=20261026+repeat、Mac 四条业务 SSH + 独立控制流、10s 客户端超时、max-inflight 1536、每流 256 连接；每臂 repeat 1–5，臂顺序逐轮交替。
  - 复用既有私有 env、`bcl_s1` 实验表、`bcl-s1-redis`、既有端口/cpuset/内存，以及全 key 审计、CSV、A.2 `calculate`、correctness 和 `bench_run` 登记。
  - 启动时要求干净工作树、冻结提交、二进制 SHA256 与镜像 ID/revision 一致；整个批次开始和结束各核对一次 `bcl_s1.items` 聚合指纹，每轮只用既有 `legacy.restore(ids)` 做逐 ID 局部恢复与对账，避免额外全表扫描改变下一轮条件；不触碰共享 `bcl.items`，不清理共享 Redis。每轮 `.done.json` 只记录局部恢复和本次结果，不声称做过全表指纹。
  - 质量门包含：客户端 `valid`、A.2 真值 `valid`、源审计 `ok`，以及缓存计数器证明的实际路径：gate-only 要求 `deletes == writes && sets == 0`；write-only 要求 `deletes == 0 && sets > 0` 且门控回填计数为 0。任一轮失败即保留现场并停止，不自动补跑。
- `scripts/p2/s1_single_branch_report.py`
  - 离线汇总：只读新 `.local` 结果与旧 `docs/measurements/2026-10-28-s1-v2/raw/race` 的 A/B/B-off repeat 1–5；输出每轮陈旧数/成功读、5 轮汇总比例、逐轮比例中位数/最小/最大、源完整读计数和 trace 事件计数。生成表之前强制校验：A.2/客户端/源 correctness 三方有效、源审计通过、每臂恰为 repeat 1–5、单一源版本、新旧都符合 95:5、400 req/s、10s warmup、32s window、50ms fill delay 和固定 data version；新臂还要求 `path_counters_ok` 为真且缓存计数器可复算出对应写路径。旧参考源必须为 `a00e151`，新源必须单一且与 `--source-commit`（若提供）一致；任何不合格轮次或参数漂移直接拒绝，不生成看似正式的表。
  - 输出固定写明跨批次限制：旧参考为 `a00e151`，新臂为之后冻结的提交，只作描述性对照，不作同提交因果估计。
- `scripts/p2/test_s1_single_branch.py`
  - 合成数据验证控制器臂配置、交替顺序、臂名长度/字符限制、路径计数判定、5 轮汇总口径、trace 挂载/归档目录契约，以及参数漂移、无效轮次、错误路径计数、混合源版本、旧参考源前缀和 `--source-commit` 不匹配的拒绝；同时只读验证公开旧 race 归档可被离线汇总读取。
