# 设计取舍

最后更新：2026-10-09；Codex；本轮源码与测量来源统一见 docs/measurements/2026-10-09-fourth-review.json（仓库根目录）；历史章节记录当时结果。

E1 原有 store 单调版本成为缓存判断依据；用 Redis Lua 原子比较版本后写入，拒绝延迟读者的旧版本填充，避免单独 GET/SET 中间被写者插入。Lua 用十进制长度与字符串比较，避免 2^53 以上版本被 double 舍入。

缓存故障时写入 source 已成功，不把缓存失败返回成写失败，否则调用者重试可能重复写。返回 degraded=true。恢复后缓存可能仍有旧值，严格模式读取 source 当前版本，匹配才采用缓存；不匹配直接 source 回退并修复缓存。这牺牲读数据库的减负收益，换来缓存断连、TTL 过期与丢失更新通知后的正确性。此实验明确不把该方案称为高吞吐生产缓存。

生产扩展可引入源存储事务 Outbox、消费版本水位与修复任务，降低逐次验证成本，但需要新增持久源库、消息恢复验证。本次不以没有实测的方案替代严格模式的证据。

source 是内存 store，重启丢数据；Redis 真实集成已验证，但不声称数据库持久性、跨服务写入或完整导购排序。推荐按候选 ID 去重、库存与预算过滤，价格升序、同价 ID 字典序排序。
## 2026-10-02 E1/E2取舍

E1按价格与ID排序并去重，让请求中重复SKU和顺序变化不影响候选列表。E2采用标准库TCP/JSON，避免引入不需要的协议依赖；单一权威帧处理输入，同帧不可变snapshot广播，connection fencing与单调seq分别防旧连接写入及重放。恢复token随机生成、只在welcome发送；仍是内存单房间实验。输入/输出均有界，慢连接关闭而非拖住帧循环。详见E2 README。此前章节为历史记录。


## 2026-10-07 Codex：W8–W10

E3独立C++工程缓存AST与重解析共用相同语义，输入大小/节点/嵌套均有界。E4独立Go模块；到达顺序保留以观察装箱和碎片效应，抢占仅成功方案提交；逐优先级贪心不声称全局最优。不同实验不强行混入Go workspace。


## 2026-10-08：E3批量过滤与枚举求值

优先采用运算符枚举，将字符串判断从逐文档热路径搬到一次解析阶段；继续递归AST，避免为短路新增跳转/栈语义的字节码复杂度。旧字符串实现只作为冻结基线，不由枚举代码反向生成，差分比较数值与异常。批量API接收只读span并输出值或下标，顺序执行、失败立即终止并给出文档下标；调用者可分块，不隐藏单文档错误或返回难以判断完整性的部分结果。

四模式测量使用同一数据及输出分配策略，轮换顺序，结果完整校验移出计时区。批量API的价值首先是一次解析与清晰过滤契约；是否比调用者自行循环快，要以同批次实测为准，不能把批量接口直接称为向量化提速。规模测量仍是单机合成文档，不推导生产吞吐。


## 2026-10-08：E4被驱逐重排与放置策略组合

保留preempt=spread+抢占兼容，新增preempt-binpack将放置与抢占能力组合；对比必须分别说明收益来自装箱还是驱逐。重排按优先级再尝试空闲节点，不允许重排继续驱逐，从而有界终止；未能恢复的任务显式Pending，历史Preempted不可当作最终失败。Rejected与被驱逐等待区分，离线函数不虚构持续控制循环。

按节点增量维护双资源占用，失败抢占在副本试算、成功才扣除，独立全量重算在所有到达前缀测试中核对。正常选择O(nodes)，抢占与Pending重排仍有扫描成本，不称全流程线性或生产级。E3的批量/枚举只证明本机合成求值优化，索引/线程/列式布局/百亿规模仍未覆盖。


## 2026-10-08：缓存双模式、输入隔离与抢占启发式（Codex）

E1 strict保留正确性默认，cache-first明确返回未校验来源，展示源负载和恢复期陈旧读取的取舍，不把TTL说成严格SLA。E2每连接队列/处理预算隔离洪泛，断线保留30秒后回收身份；代价是到期不能恢复、总帧成本随在线玩家增长，多开连接不受账号配额控制。E4低优先级顺序不变，同优先级优先释放缺口资源，避免小任务先驱逐的已复現用例；两资源贪心不保证全局最优。E3已做枚举和顺序批量，不代表索引、多线程或百亿检索。


## 2026-10-09：接口一致性、局部补偿与可解释对照（Codex）

统一Item snake_case是可见契约变化，Redis切v2键隔离旧格式，避免字段标签不兼容时读成零值。本地失败修复队列保存版本水位，读时强制回源并修复；版本比较防止旧读者清除新失败，溢出保守关闭未校验读。不是持久Outbox，重启和多实例尚依赖TTL/严格模式。

E2对IP限制TCP和保留身份，缓解单主机名额占用而非伪装成账号认证；connected字段明确断线宽限，到期移除需客户端处理。E4分别构造装箱、驱逐、组合场景，组合使用更多驻留资源但驱逐更多，不用一个总分掩盖代价。E3名称绑定到数组slot，共享AST语义，含/不含转换成本两组测量，schema静态缺失与运行期短路缺值分开。

## 第四轮：并发与类型边界（2026-10-09）

E1空队列用原子dirty快速判断；不在nil值接收者中隐式创建队列，避免多个Service副本各自创建、丢失跨请求修复标记。改成cache-first缺队列显式配置错误，在写入前拒绝；NewService/HTTP仍默认启用。标记和overflow不盲目按TTL清理，因为Cache接口无寿命上界、旧回填可刷新TTL，当前保守退化是未解决的可用性限制。需要缓存侧栅栏等协议后再做安全回收。

E2原生IPv6用/64聚合TCP/身份配额，mapped IPv4归一成IPv4，不把IP策略称为账号保证。E3新Bound私有拥有克隆树，只暴露只读evaluate，摆脱调用方“不要重绑”的约定；解析树不暴露Bound内部，构造成本不在热路径。E4按驱逐事件分别累计两类打断资源，拒绝不计入；这是资源量，不是运行进度成本，仍需同时读拒绝、接纳、最终占用。
